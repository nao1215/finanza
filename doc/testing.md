# Testing

`just ci` runs everything below except the nightly job and mutation testing. Tests run on the Erlang and JavaScript targets, on the Gleam floor (1.14.0, OTP 27, Node 22) and on the latest Gleam 1.x, on Linux, macOS and Windows.

## Examples and unit tests

Every module has a test file under `test/`: decimal parsing, arithmetic and every rounding mode at `2.5`, `3.5`, `10.005` and their negatives, money formatting and allocation, interest and amortization schedules, and card validation with public test PANs only. `test/dig_round1_boundary_test.gleam` and `test/dig_round9_boundary_test.gleam` probe the limits (JavaScript's safe-integer cap, empty and huge inputs). `test/dig_round11_range_test.gleam` pins the range of a decimal from both sides of each bound (exponent -28 and 15, coefficient 2^53 − 1, 1,000 bytes of input), feeds huge exponents, digit counts and inputs to `parse`, compares `divide` with an unbounded-integer oracle on Erlang, and checks `allocate` near 2^53 on both targets. `test/dig_round17_bounded_work_test.gleam` pins the work the interest functions do: the exact value stops at `tvm.exact_limbs` limbs, every bound keeps its precision for rates near 2^53 and near -1 over 1200 periods, ties still round from the exact value, and the `card` functions reject input over 1,000 bytes. `test/readme_test.gleam` runs the README examples, and `test/support.gleam` holds the `let assert` helpers for inputs known to be in range.

## Generated properties

`test/property/` and `test/dig_round2_property_test.gleam` / `test/dig_round8_property_test.gleam` use metamon to check algebraic laws: commutativity, associativity and distributivity of decimal arithmetic, string round trips, `allocate` preserving the total, Luhn on an appended check digit, and an amortization schedule whose balance closes to zero.

## Metamorphic relations

`test/dig_round3_metamorphic_test.gleam` and `test/dig_round6_metamorphic_test.gleam` check relations between runs: scaling, inverse operations and round trips through minor units.

## Differential testing

`test/dig_round5_differential_test.gleam` and `test/dig_round10_differential_test.gleam` compare arithmetic, rounding, PMT, FV, PV, EAR and amortization with values computed by Python `decimal` and published Excel examples. `test/differential/python_test.gleam` runs about 2,950 cases generated by `scripts/python_differential.py` with Python's `decimal` at 200 digits on both targets: `parse`, `to_string`, `add`, `subtract`, `multiply`, `divide`, `round` and `compare` with random and boundary inputs in every rounding mode, and every interest function, whose expected values the script also computes with exact fractions and stops if the two disagree. The range rules of `finanza/decimal` are applied on top of Python's results. To change the cases, edit the script, run `python3 scripts/python_differential.py > test/differential/python_cases.gleam` and `gleam format test/`. On Erlang, `test/property/interest_oracle_test.gleam` compares `simple`, `future_value`, `present_value`, `payment` and `effective_annual_rate` with exact fractions in bignums for random principals, monthly and 16-place rates, negative rates and up to 400 periods, and with inputs made to land exactly on ties (rates whose `1 + rate` is a ratio of powers of 2 and 5), where it also checks that the exact value is computed within its limit. `test/property/interest_work_test.gleam` checks on both targets that every bound stays within a few limbs of its precision and that the exact value is either the rounded result or `PrecisionExceeded`, for rates near 2^53, near -1 and with 28 places over up to 1200 periods. `test/property/rounded_number_test.gleam` checks the exact numbers the interest functions compute with, and `limb.divide` with limbs such as 9999999 and 1 and with exact multiples. `test/property/decimal_oracle_test.gleam` compares `decimal.round` and `decimal.divide` with an oracle that does one integer division and applies each of the seven rounding modes to the remainder, for random coefficients, exponents and precisions, with ties (`...5`, `...50`) mixed in. It also checks that `round` always returns exactly `digits` fractional places.

## Fuzzing

There is no coverage-guided fuzzer for Gleam. `test/dig_round4_fuzzing_test.gleam` and `test/dig_round7_fuzzing_test.gleam` pump random and malformed strings through every parser and require a typed error instead of a crash, and the nightly job below repeats every property with more inputs.

## Nightly runs

`.github/workflows/nightly-property.yml` runs the whole suite ten times with `METAMON_RUNS_MULTIPLIER=10`, each pass with a new seed. A failure report prints its seed, so the case can be replayed with `Config(..default_config(), seed: Some(seed))` and kept as a regression test.

## Mutation testing

`gleam run -m metamon/mutation` changes one operator, `!` or boolean literal in a module under `src/` at a time and runs `gleam test --target erlang` on each change. `.github/workflows/mutation.yml` mutates the modules a pull request changes and fails on a survivor that `doc/mutation/baseline.json` does not list; the weekly run mutates every module. `just mutation` runs everything and `just mutation-record` writes the baseline.

The first run (2026-11-27) scored 79.6%. Tests were then added for `validate` at 12 and 19 digits, `mask` when the kept digits cover the whole number, January and an invalid current month in `expiry_valid` and `parse_expiry`, a sign after a digit, a trailing zero just below 2^53, `to_int` with a positive exponent and with 15 places, a product that drops 15 trailing zeros, a sum scaled by 15 places, an `allocate` share that wraps the ratio total, adding a zero with more places, `present_value` at a rate of -1 over zero periods and `effective_annual_rate` with zero compounds, and the score rose to 82.8%. The baseline is the union of the survivors of two full runs after the new tests; a mutant that one run reported as lived only because it looped until earlyoom stopped the test process was rerun by hand and left out. The 91 survivors left change nothing that a caller can see:

- `card` (5): the sign of the Luhn sum, which only matters modulo 10, a doubled digit that is never 9, a prefix that always parses because the length was checked first, and the two clamp bounds of `mask`, which return the same value at the bound.
- `decimal` (24): the product of two signs, which is the same divided (2); range checks of `divide`, `round` and `checked` that a later check repeats (3); comparisons at zero, where both branches give the same result (6); overflow guards next to 2^53 - 1, where the boundary value cannot occur or another path gives the same result (10); the second-sign flag, which the position check already covers (1); and the zero padding of `compare_by_magnitude`, which is only reached when the leading digits are at the same position and the exponents differ by more than 15, so the digit strings never share a prefix (2).
- `money` (2): the sign of an amount of 0, and a mutant of `multiply_modulo` that loops forever. A run kills it when the test suite times out, but on a machine where earlyoom stops a runaway BEAM with SIGTERM, the BEAM exits with status 0 and the run reports it as lived, so the baseline lists it as lived. The range check of `checked` is listed as lived for the same reason: one run timed it out and another reported it as lived.
- `internal/limb` (9), `internal/rounded` (26) and `internal/tvm` (25): the limb arithmetic and the interval bounds behind `interest`. They choose whether a bound is rounded up or down, how many limbs it keeps, or the quotient limb estimate that `correct_down` corrects, and include a branch of `add_scaled` that the multiplication never takes and digit checks that the public functions make first. A looser bound only makes `tvm` retry at a higher precision, and the exact oracle tests get the same results.

Brand detection checks UnionPay (`62`, 16 to 19 digits) before Discover, so Discover's co-branded range 622126 to 622925 is reported as UnionPay. The Discover rule for that range could never match and was removed in 0.12.0.
